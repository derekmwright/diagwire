New required changes: **4, fewer than round 1’s 8.**

1. **G3 creation, line 31 — pragmas cannot all join the creation transaction.** Applying WAL mode inside a transaction is prohibited; enabling foreign keys there is a no-op. The wording puts application ID, pragmas and migrations “in one transaction.” **Smallest fix:** configure and verify connection pragmas outside the transaction; transact application ID, schema and version together. [SQLite pragma rules](https://www.sqlite.org/pragma.html)

2. **G3 migration, line 32 — backup coverage contradicts ordering.** Backup completes before `BEGIN IMMEDIATE`, yet must contain every commit before that lock. Another writer can commit between those steps; a consistent snapshot alone cannot meet the promise. **Smallest fix:** specify exclusion of writers across backup and migration-lock acquisition, or explicitly define backup coverage at its snapshot boundary. The API may remain deferred. [SQLite backup semantics](https://www.sqlite.org/backup.html)

3. **G6, line 56 versus G5/schema — duplicate-vehicle retraction is undefined.** G6 promises “the duplicate is retracted,” but `vehicle` is an immutable anchor with no chain/retraction state; only identifier and record retractions are specified. **Smallest fix:** define vehicle retraction through an append-only lifecycle record, including default-query behavior, or replace the promise with the exact supported identifier-retraction behavior.

4. **G1, line 21 — version claims need qualification.** The cited advisory supports the **3.51.3 fix**, but explicitly lists fixed backports **3.44.6 and 3.50.7**; the categorical affected-version range omits these exceptions. A runtime minimum also cannot detect losing `bundled` when system SQLite meets that minimum. **Smallest fix:** mention backport exceptions and say the check catches an *older runtime*, not loss of the feature. [WAL-reset advisory](https://www.sqlite.org/wal.html#walreset)
