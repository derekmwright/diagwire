VERDICT: CHANGES REQUIRED

## Required changes

1. **G2/G6 — conflicting dependency rules.** G2 permits front ends to depend directly on `garage`; G6 forbids this; accepted DR-0001 D1 permits only operations. **Smallest fix:** remove G2’s exception and route garage access through operations.

2. **G6/G5 — conflicting MCP capabilities.** G6’s decision permits vehicle/alias creation, while its consequence and G5 prohibit it. This leaves the public write boundary undecidable. **Smallest fix:** make G6’s decision match the stated v0 tools: service events, notes and their supersede forms; vehicle/alias management through CLI.

3. **G1/G3 — unsafe “one file” backup description.** WAL is persistent database state; copying only the main file can lose committed transactions or produce corruption. G3 promises to “copy the file aside” without imposing a consistent-backup requirement. **Smallest fix:** describe one logical database with sidecars; require a SQLite-consistent backup, successful before migration, and abort migration if backup fails. The exact API can remain deferred. [SQLite WAL documentation](https://www.sqlite.org/wal.html)

4. **G4/replay 3 — CHECK constraint overclaims provenance protection.** Restricting session source strings does not prevent an import path from inserting `diagwire-read` or linking to an existing measured session. No capability boundary currently decides who assigns those sources. **Smallest fix:** separate measured-observation and note/import entry points; assign source internally; deny imports access to session/snapshot writers. Reword replay 3 to credit that boundary, with a negative test. If canonical captures become writable, require a reference to their D4 provenance stamp rather than just a tool name.

5. **G3/replay 4 — creation and refusal protocol missing.** A fresh database has no garage application ID, yet G3 says to refuse foreign files without defining the initialization exception. Checking headers before writes also needs ordering relative to WAL setup and concurrent migration. **Smallest fix:** distinguish creation from opening; never initialize an existing unrecognized database; validate before mutating configuration; recheck versions under the migration write lock. Define whether “byte-identical” includes sidecars or only the main file.

6. **First-slice test 5 — cannot necessarily settle its stated unknown.** A migration that fails after its first statement may fail before `user_version` changes. The test could pass even if that pragma escaped rollback. **Smallest fix:** change schema, set `user_version`, then inject failure; verify both revert.

7. **G8/replay 7/Q5 — redaction contract is incomplete.** G8 delegates MCP redaction to the export policy, but that policy explicitly exempts aliases and names; a vehicle label or alias can itself contain a VIN. Q5’s “provider never sees VINs unless the user asks” exceeds the admitted best-effort guarantee. **Smallest fix:** apply redaction to every outgoing string, including labels, ambiguity candidates, echoes and errors; state the residual consistently. Decide that logs omit garage payloads and that database, sidecars and backups receive user-private filesystem access. This preserves the settled MCP-disclosure ruling.

8. **G1/replay 5 — durability policy missing.** Atomicity is distinct from retaining acknowledged writes after power loss. WAL with `synchronous=NORMAL` can lose committed transactions; `OFF` can compromise consistency. The record does not choose a setting. **Smallest fix:** require and verify `synchronous=FULL` on write connections, or explicitly accept a weaker durability guarantee. Also require a bundled SQLite version containing the documented WAL-reset corruption fix when pinning dependencies. [SQLite synchronous documentation](https://www.sqlite.org/pragma.html#pragma_synchronous), [WAL-reset advisory](https://www.sqlite.org/wal.html#walreset)

## Optional suggestions

- Correct G1’s categorical JSON/TOML claim: file formats themselves do not preclude locking or atomic replacement.
- Define “latest measured faults” per vehicle **and ECU**, and expose newer failed attempts alongside older complete snapshots.
- Clarify whether retracted heads appear as tombstones or disappear from default queries.
- No substantial schema over-design found: retaining deferred tables as future sketches is sufficient. Seven mutation-based negative controls are heavier than this first slice needs; prioritize refusal, rollback and provenance boundaries.

## Checked and found sound

- **Replays 1–9:** 1 refuses received ambiguity but cannot force the model to ask; 2 protects supported paths, honestly excludes shell access; 3 overclaims as above; 4 needs opening rules; 5 has a valid transaction requirement, but injected failure does not demonstrate process-death recovery; 6 honestly defers conflict settlement; 7 needs consistent redaction; 8 honestly limits structural protection to the storage crate; 9 correctly serializes writes and surfaces contention.
- Header offsets, SQLite’s non-use of `user_version`, per-connection foreign-key enabling, `RAISE(ABORT)` constraint errors, WAL host restrictions and immediate-transaction contention match the cited documentation. [Pragmas](https://www.sqlite.org/pragma.html), [foreign keys](https://www.sqlite.org/foreignkeys.html), [triggers](https://www.sqlite.org/lang_createtrigger.html), [transactions](https://www.sqlite.org/lang_transaction.html)
- rusqlite 0.42.0 documents the 5000 ms changeable busy-timeout default, `Immediate`, and the `bundled` feature. The explicitly unverified pragma rollback, bundled-build details and Windows roaming claims are not disguised as verified facts. [Connection](https://docs.rs/rusqlite/latest/rusqlite/struct.Connection.html), [TransactionBehavior](https://docs.rs/rusqlite/latest/rusqlite/enum.TransactionBehavior.html), [features](https://docs.rs/crate/rusqlite/latest/features)
- D6 hardware restrictions, D7 temporary-data boundary and D10 complete-versus-failed outcomes remain intact. No hardware, database or cargo execution; no files changed.
