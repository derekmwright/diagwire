## Required items
1. **G2/G6 dependency conflict (ruling 1): done.** G2's line is reworded: front ends read the garage only through operations. The front-end exception and the "amend D1" flag are removed.
2. **G6/G5 MCP capabilities (ruling 2): done, matching the architect's G6 line, not the judge's smallest fix.** MCP adds vehicles and identifiers, plus service events and notes with their supersede and retract forms. G5 now covers `vehicle` and `vehicle_ident` as append-only. The schema replaces `vehicle`+`vehicle_alias` with an immutable `vehicle` anchor plus a `vehicle_ident` chain (label/alias/VIN/chassis), so labels, VINs learned later and dropped aliases are supersedes or retractions. Live alias/VIN uniqueness is checked inside the write transaction. The first slice includes vehicle and identifier writes.
3. **Backup (ruling 3): done.** G1 defines one logical database as the main file plus sidecars and says nothing copies the main file alone (S-wal). G3 requires a SQLite-consistent backup before any migration or the migration aborts. The API is deferred and the candidates are marked unverified.
4. **Provenance (ruling 4): done.** G2 has two capabilities: `RecordWriter` (maintainer-entry/imported-note) and `ObservationWriter` (diagwire-read), with source set internally and no source parameter anywhere. Import and MCP hold only `RecordWriter`. The CHECK is demoted to a backstop. A future canonical-capture writer must reference its D4 stamp. Replay 3 is reworded to credit the boundary and has a negative test with an NC, scheduled for the operations slice (sessions don't exist in slice 1). Slice-1 test 2 covers the internal source assignment with an NC.
5. **Open vs create (ruling 5): done.** `create` refuses existing paths and sidecars. `open` uses flags without `SQLITE_OPEN_CREATE` (rusqlite's default `open` includes it, R-conn). It validates app id (0 counts as foreign), version and SQLite version before any pragma change, and rechecks the version under the migration's `BEGIN IMMEDIATE`. **Dissent (G3, r2):** "byte-identical main file plus sidecars" only holds for a cleanly closed garage, because S-wal says the last close checkpoints and deletes the WAL. I propose a definition for the leftover-WAL case. Test 4 uses clean files.
6. **Test 5 (ruling 6): done.** The test-only migration creates a table, sets `user_version`, then fails, and the test checks that both revert. It's a stop condition if the version escapes.
7. **Redaction (ruling 7 + Q5 answer): done.** G8 is written for redaction-on. One outgoing filter covers every string sent to the AI client or an export: results, labels, aliases, ambiguity candidates, echoes and errors. The include switch is user-side only, never a model-settable parameter. The best-effort residual is stated once in G8 and referenced in replay 7. Logs carry no payloads. On Unix the directory is 0700 and files 0600, with database, sidecars and backups in one directory. On Windows the ACL is relied on (unverified). Q5: the "never sees" overclaim in its parenthetical is fixed and the answer recorded with the maintainer's wording and date. The G8 line's "(pending Q5)" becomes "(Q5, answered 2026-11-14)".
8. **Durability (ruling 8): done.** `synchronous=FULL` is set and read back on every write connection, with S-sync cited (FULL is ACID in WAL; NORMAL may roll back after power loss). The WAL-reset advisory (S-walreset) says the bug affects 3.7.0–3.51.2 and is fixed in 3.51.3. **Confirmed:** at tag `v0.42.0`, rusqlite's `libsqlite3-sys` is 0.40.0 and its bundled `sqlite3.h` says `SQLITE_VERSION "3.54.1"`. For comparison, v0.41.0 → 3.54.0 and v0.40.0 → 3.53.1. The slice pins `rusqlite =0.42.0`, and open refuses a runtime `sqlite_version()` below 3.51.3 (test 7, plus a stop condition).
