## Spike-vs-decision mismatches
1. D1: `Session` hard-wires `hsfz::Connection` and `hsfz::Error` (`crates/diagwire/src/lib.rs:20,31-33`), so there is no transport seam. The CLI calls `hsfz::discover` directly (`crates/cli/src/main.rs:47,84`). HSFZ framing sits in the transport crate while DS2 framing has a codec crate. `ds2` is unused (cargo warning).
2. D2: `scan_dtcs` uses the `std::time::Instant` wall clock (`diagwire/src/lib.rs:5,75`), so a paused-clock test can't drive it. rmcp isn't a dependency, so "rmcp is tokio-based" is unverified here.
3. D3: no authority has been exercised. UDP 6811 discovery (`hsfz/src/lib.rs:22,233-246`) conflicts with `EDIABAS.INI:626-630`, which calls 6811 a TCP control channel. The record leaves this unresolved.
4. D4: no fixtures, stamp format or loader. All test vectors are hand-written.
5. D5: no job files. Requests are hard-coded (`uds/src/lib.rs:29-41`). This doesn't conflict with v0.
6. D6: no MCP yet. The public raw `Session::request` (`diagwire/src/lib.rs:44-61`) would let any front end send state-changing services past a tier check, and it panics on an empty request (`:45`).
7. D7: no fakes for any transport. `connect` opens a real socket on the fixed port 6801 (`hsfz/src/lib.rs:128-140`). `discover` broadcasts for real, and `dtc` without `--ip` triggers it (`cli/src/main.rs:56-59`). Nothing mechanical enforces the boundary.
8. D8 and D9 match the spike.
